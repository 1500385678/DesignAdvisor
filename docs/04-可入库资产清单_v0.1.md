# 可入库资产清单 · v0.1

> Phase 0 任务 2 产物 · 2026-08-31 · T5(无 Figma 权限,本地骨架版,Phase 1 OAuth 后回填真实 `figma_ref`)
> 数据对齐:`docs/02-设计资产元数据-schema.md` v0.1

## 1. 目的

在没有 Figma API 权限之前,**先把"我们会从 Figma 拉什么"的目录骨架定下来**,让:
- Phase 1 #1 资产库(`GET /api/v1/assets`)有第一波 metadata 可 fake-load,设计师能 dogfood
- `02-schema` 字段(`kind` / `status` / 治理 / 关联)有真实数据形态做回归
- OAuth 接入后,只要按本清单遍历即可,不需要再设计一次目录

不替代 Figma OAuth 接入(Phase 0 #3),只解决"清单/分类/字段对齐"的本地前置。

## 2. 四类资产初稿(组件 / 页面 / 令牌 / 参考)

按 `02-schema` §3 `kind` 枚举,本清单**只覆盖 4 类**(`brand` / `template` / `guideline` 留待 Phase 1 再展开):

| 序号 | `kind` | 名称 | 预期来源 | 关键字段 | 数量预期 |
|---|---|---|---|---|---|
| §3 | `component` | 组件库 | Figma 组件库页面 | kind / code_ref / reviewers | 30-60 件 |
| §4 | `page` | 页面模板 | Figma 整页设计稿 | kind / figma_ref / supersedes | 15-30 件 |
| §5 | `token` | 设计令牌 | Figma Variables / Tokens 插件 | kind / version / purpose | 40-80 条 |
| §6 | `reference` | 外部参考 | 设计师手工收藏 | kind / tags / source URL | 不限,开放 |

> `brand`(Logo / VI 字体授权)、`template`(评审走查模板)、`guideline`(品牌手册)三类在 v0.1 暂不展开,Phase 1 #1 资产库 MVP 跑通后再补 §7。

## 3. 组件类(`kind=component`)预期清单

**字段对齐**(以 `02-schema` §2/§5 为准):
- `kind` = `component` · `status` 默认 `approved` · `purpose` ≤140 字
- `code_ref[]` 强必填(组件必须能在前端代码里找到),`figma_ref` 强必填
- `reviewers` 默认 = 该组件库 owner + 前端组长

| 类别 | 示例资产 | 预期命名空间 | 数量 |
|---|---|---|---|
| 按钮 | 主按钮 / 次按钮 / 文字按钮 / 危险按钮 / 加载按钮 | `comp/button/*` | 5 |
| 表单 | 输入框 / 文本域 / 单选 / 复选 / 开关 / 选择器 | `comp/form/*` | 6 |
| 反馈 | 弹窗 / 抽屉 / 提示 / 警告 / 加载 / 空状态 | `comp/feedback/*` | 6 |
| 导航 | 顶部导航 / 侧边栏 / 面包屑 / 分页 / 标签页 | `comp/nav/*` | 5 |
| 数据 | 表格 / 卡片 / 列表 / 统计卡 / 图表容器 | `comp/data/*` | 5 |
| 排版 | 标题 / 段落 / 引用 / 列表 / 代码块 | `comp/typography/*` | 5 |

> **小计**:32 件 · 与"30-60 件"区间对齐 · Phase 1 #1 入库时按 `comp/<类别>/<子项>` 命名。

## 4. 页面类(`kind=page`)预期清单

**字段对齐**:
- `kind` = `page` · `status` 默认 `draft` 或 `in_review`(整页一般需评审)
- `figma_ref` 强必填 · `code_ref` 选填(落地页一般有代码,概念页没有)
- `supersedes` 字段对页面特别重要(改版频繁)

| 类别 | 示例资产 | 预期命名空间 | 数量 |
|---|---|---|---|
| 认证 | 登录 / 注册 / 忘记密码 / 二步验证 | `page/auth/*` | 4 |
| 概览 | 首页 / Dashboard / 工作台 | `page/overview/*` | 3 |
| 内容 | 列表页 / 详情页 / 搜索结果 | `page/content/*` | 3 |
| 流程 | 引导页 / 空状态 / 错误页 / 404 / 500 | `page/flow/*` | 5 |
| 设置 | 个人设置 / 团队设置 / 账单 / 通知设置 | `page/settings/*` | 4 |

> **小计**:19 件 · 与"15-30 件"区间对齐 · 落地页与概念页比例按 7:3 估算。

## 5. 令牌类(`kind=token`)预期清单

**字段对齐**:
- `kind` = `token` · `version` 严格 semver(令牌改版需要全局生效性)
- `purpose` 必填(为什么需要这个令牌,避免"孤儿令牌")
- 关联:每个 token 至少挂 1 个 `code_ref`(Style Dictionary 引用)

| 类别 | 示例资产 | 预期命名空间 | 数量 |
|---|---|---|---|
| 颜色 | brand.primary / brand.secondary / text.* / bg.* / border.* / state.* | `token/color/*` | ~25 |
| 字号 | xs(12) / sm(14) / base(16) / lg(18) / xl(20) / 2xl(24) / 3xl(30) / 4xl(36) | `token/font-size/*` | 8 |
| 字重 | regular(400) / medium(500) / semibold(600) / bold(700) | `token/font-weight/*` | 4 |
| 行高 | tight(1.25) / normal(1.5) / relaxed(1.75) | `token/line-height/*` | 3 |
| 间距 | 0 / 1(4) / 2(8) / 3(12) / 4(16) / 6(24) / 8(32) / 12(48) / 16(64) | `token/spacing/*` | 9 |
| 圆角 | none(0) / sm(2) / base(4) / md(6) / lg(8) / xl(12) / 2xl(16) / full(9999) | `token/radius/*` | 8 |
| 阴影 | xs / sm / base / md / lg / xl / 2xl / inner | `token/shadow/*` | 8 |
| 透明度 | 0 / 5 / 10 / 20 / 40 / 60 / 80 / 100 | `token/opacity/*` | 8 |

> **小计**:~73 条 · 与"40-80 条"区间对齐 · 令牌命名统一 kebab-case 段,数字+单位对齐 Style Dictionary 规范。

## 6. 参考类(`kind=reference`)预期清单

**字段对齐**(与组件/页面/令牌**不同**):
- `figma_ref` **不要求**(参考是外部链接,不是 Figma 节点)
- `tags` 强必填(参考靠标签检索,不是命名空间)
- `source` 字段(URL / 截图 / PDF)在 `02-schema` 没列,需在 Phase 1 schema v0.2 补 `external_ref`(参考类专用)

| 类别 | 示例资产 | 关键字段 | 数量 |
|---|---|---|---|
| 竞品 | 钉钉 / 飞书 / Notion / Linear / Figma 自身的视觉决策 | external_ref / tags | 不限 |
| 灵感 | dribbble / behance / awwwards 收藏 | external_ref / tags | 不限 |
| 行业案例 | 银行 / 电商 / SaaS 各家设计系统 | external_ref / tags | 不限 |
| 大师作品 | Dieter Rams / 原研哉 / 深泽直人 等可引述 | external_ref / purpose | 不限 |

> **小计**:开放 · 不设上限,设计师随手收藏 · 但需走"引用规范"——外部参考必须有出处链接,避免抄袭/版权问题。

## 7. 留待 v0.2 处理(本次不展开)

- `kind=brand`(Logo / VI / 字体授权):品牌资产单独走采购/授权流程,需要法务字段,不在本期范围
- `kind=template`(评审/走查模板):与"设计评审协作 v1"模块同 Phase 1 启动,届时另起 schema
- `kind=guideline`(品牌手册 / 组件使用说明):Markdown 长文档,与本清单元数据模型不完全一致,需要扩展 `guideline` 类型字段
- `02-schema` §8 的 4 个待定项(`id` 命名空间 / tags 本体 / 同步告警阈值 / 评审记录归属),Phase 1 #1 入库前必须定

## 8. 字段使用约定(给 Phase 1 资产库 MVP 的口径)

| 字段 | 在本清单的取值约定 | 入库时是否必填 |
|---|---|---|
| `kind` | 见 §2-§6 | ✓ |
| `status` | 组件/令牌默认 `approved`,页面默认 `draft` | ✓ |
| `version` | 初始入库 `0.1.0`,首次评审通过后跳 `1.0.0` | ✓ |
| `purpose` | 简短陈述,不超过 140 字 | ✓ |
| `tags` | 全部小写,空格分隔,逗号分隔数组 | ✗ 但推荐填 |
| `figma_ref` | 组件/页面/令牌 必填,参考类不填 | ✗(按 kind) |
| `code_ref[]` | 组件/令牌 必填,页面/参考 选填 | ✗(按 kind) |
| `reviewers` | 资产 owner + 1-2 个跨职能(产品/前端/品牌) | ✗ |
| `supersedes` / `superseded_by` | 改版时必须填,避免孤儿版本 | ✗ |
